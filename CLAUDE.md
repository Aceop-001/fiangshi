## MISSION
Fiangshi is a pre-payment counterparty oracle for x402 agent payments. Given a paid endpoint URL: probe the 402 unpaid, resolve the payee wallet, score it from a cached snapshot, let SERV Reasoning adjudicate under five deterministic Vows, and return ALLOW/REVIEW/BLOCK with quoted evidence and a signed, re-runnable receipt. Advisory only. Tagline: "The model advises, the vows decide."

## NON-NEGOTIABLES
- FAIL CLOSED. Missing signal, timeout >15s, schema violation, model failure => REVIEW. Never ALLOW by default. Never BLOCK without a machine-checkable reason.
- VOWS OVERRIDE THE MODEL. Five deterministic rules run AFTER the model and may only lower the verdict. The model has zero authority to raise it.
- NO CUSTODY. Fiangshi never holds funds, signs, or sends transactions.
- TRACEABILITY. Every number in README/artifacts reproducible by a committed script. No script, no number.
- NO INVENTED API FIELDS. Run --help / read docs before every integration; copy names verbatim. If a field is missing: stop and ask.

- NO SCOPE CREEP. No dashboard, auth, admin panel, or DB server.

## SCORING (pure, each component in [0,1])
score = 25M + 20P + 20R + 15I + 10E + 10C
- M maturity (log age+tx) · P provenance (CEX 1.0 / fresh funder 0.6 / shared 0.2 / mixer 0)
- R revenue reality (distinct+repeat payers, log-capped) · I identity (corroborated)
- E exposure (concentration) · C corroboration (extracted field coverage)
Bands: >=80 ALLOW · 50-79 REVIEW · <50 BLOCK

## VOWS (pure functions, table-driven tests, precedence as listed)
| vow | rule | band |
|---|---|---|
| age | payee age < 48h | BLOCK |
| kinship | funder shared with >=3 other catalog payees (<=2 hops) | BLOCK |
| history | distinct_payers == 0 AND price > $0.50 | REVIEW |
| identity | claims uncorroborated AND age < 7 days | BLOCK |
| silence | any required signal missing | REVIEW |

## PIPELINE — implement in order, each gated by tests
1. Probe: unpaid GET, parse 402 (headers + body), terms_hash = sha256(canonical).
2. Snapshot: enumerate endpoints, dedupe payees, ONE batched query per metric over the whole set, write data/snapshot.json + snapshot_id = sha256(payload).
3. Score: pure functions, boundary tests at 0/mid/1/missing.
4. Vows: pure, one test each + a precedence test where model=ALLOW and vow=BLOCK.
5. SERV: strict JSON, validate every cited signal exists and every quote is a substring of stored evidence. Fail -> retry once stricter -> degraded verdict.
6. Dolphin: prose -> typed identity fields only, hash-cached, no verdict authority.
7. Receipt + Ledger: canonical JSON, sha256, prev_hash chain, verify command, drift rules (band crossing 50/80, payee rotation, funder change, >10% price drift, dormancy >=60d reactivation), policy decay 72h.
8. API: GET /v1/check?url= · GET /v1/payee/:addr · POST /v1/monitor · GET /v1/index.json · GET /v1/badge/:addr.svg. Seller x402: 402 -> verify X-Payment -> facilitator settle -> deliver.
9. Lab: 5 archetypes (burner, sybil, migrator, sleeper, lookalike) + 10 clean controls; emit artifacts/matrix.md with detection, band, false positives, latency.
10. Index: static page from snapshot + ledger, cluster view, regenerates hourly.

## Interpretation notes (decisions taken where the spec is silent — see README "Design decisions")
- Final band = min(score band, model band, vow band). Degraded model caps at REVIEW. Model can only lower.
- Vow reported = most severe fired vow; ties broken by listed precedence.
- Kinship ignores funders labelled CEX (an exchange hot wallet funding many sellers is normal).
- Invalid numbers (negative, NaN, future timestamps, self-funding) are sanitized to "missing" → silence → REVIEW. Data errors never BLOCK.
- Receipts are hash-chained (sha256 + prev_hash), NOT cryptographically signed. Decided 2026-11-08: no signature field, no signing key. "Signed" in the mission means tamper-evident via the chain. Do not add signing without asking.

Surf usage facts (verified 2026-11-08, see artifacts/capability.md):
- Structured output: `--json` (alias for `-o json`). Credits are always in `meta.credits_used`.
- POST commands (`onchain-sql`, `onchain-sql-job-create`, `onchain-sql-preflight`) take a JSON body on stdin: `{"sql": "...", "max_rows": N}` (max_rows 1..10000).
- Tables are `agent.<name>`. Payee facts come from `agent.base_transfers`. Every query MUST filter on `block_date` (partition key). Never wrap addresses in `lower()`; lowercase the literals instead. Never OR `from`/`to`.
- A UNION/join/multi-branch query needs an async job (`onchain-sql-job-create`), which REQUIRES an API key (UNAUTHORIZED without). On the free tier, use the two single-branch sync queries: `scripts/surf/payee-inbound.sql` and `payee-outbound.sql`.
- Window: 365 days (`block_date >= today() - 365`). Wallet age is therefore a LOWER BOUND (first_seen within the window).
- Billing is per call by tier, not per payee: SQL measured 5 credits/call whether 2 or 12 payees. Labels: 1 credit per ≤100 addresses (measured). Batch payees; never loop per payee.
- Entry points: `npx tsx scripts/surf/payee-facts.ts <payee,...> [--tag t] [--only inbound|outbound]` and `npx tsx scripts/surf/labels.ts <smoke.json> <out.json>`. Both are budget-guarded.
