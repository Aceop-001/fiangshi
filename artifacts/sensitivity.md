- **A, current.** Every unlabelled shared funder with fanout >= 3 blocks.
- **B, calibrated (not applied).** Same trigger; fanout >= 20 on one unlabelled funder becomes REVIEW with the flag `kinship_suspected_exchange`. It creates 0 new BLOCKs, but moves BLOCK by -33.2% and REVIEW by +20.4%, past the 15% limit set for this pass. It would also turn the lab's sybil case B2 (fanout 20) from BLOCK into REVIEW, which lowers recall. So it was measured and not applied.
- **C, worst case.** If every unlabelled shared funder were an exchange, kinship would never fire on them and their provenance would score as an exchange. This is the upper bound on false blocks: at most 214 of the 286 BLOCKs depend on those funders being something other than exchanges.

## Why the funders are still unlabelled

All 19 funders behind a kinship BLOCK were sent to Surf `wallet-labels-batch` on 2026-11-09 (artifacts/audit.md, cluster table). Surf returned no entity name or type for any of them. Four of them each funded 21 or more census payees (48, 39, 33 and 21), covering 141 payees.
