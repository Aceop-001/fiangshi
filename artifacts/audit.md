# Payee audit — x402 Bazaar catalog, Base

Generated by `npx tsx scripts/audit.ts report` from `fixtures/audit/` (sample, checkpoint, probes). Surf data through 2026-11-09T02:57:19.701Z; 90-day window. **Run incomplete:** balance 72 − 1 for wallet-labels-batch would fall below the 72-credit buffer. Checkpoint saved.

## Method

1. Enumerated the public Bazaar catalog (`scripts/enumerate-bazaar.ts`, 0 credits): every resource with its `accepts[0].payTo`, network and price.
2. Deduped Base (`eip155:8453`) payees. Base (eip155:8453) payTo from the x402 Bazaar catalog, deduped, ordered by sha256(payee), first 1923.
3. Probed one live endpoint per sampled payee, unpaid (1 req/sec, 0 credits), to check the catalog payee against the live 402.
4. Ran batched Surf SQL over `agent.base_transfers`: payee inbound + payee outbound + funder outbound. Each query covers the whole batch, never one payee at a time. Then `wallet-labels-batch` in groups of ≤100 addresses.
5. Scored with the deterministic policy (score + vows, no model) under **E v2** (payer concentration).

**Window: 90 days, uniformly.** Every payee in the scored set was queried over the same `block_date >= today() - 90` window. This is a method choice for recency: it keeps the 50-payee synchronous query inside Surf's scan budget, which the 365-day window exceeded on busy wallets, and it scores recent behaviour. Earlier 365-day rows are archived in `checkpoint-*-w365.json` and are not scored.

**M (maturity) is two-tier for this dataset:** a payee whose first transfer sits at the window start is *established* (≥ 90d, full age credit); a younger payee gets a log curve up to 90 days. The volume half (transfer count) is unchanged. A full 365-day maturity curve on windowed data is a roadmap item.

## Caveats

- Ages are floors. 84 payees sit at the window start, so their true age is ≥ 90d, never stated in years. The 48h age vow is unaffected: its threshold sits inside the window.
- The band counts above are the only split this report states: they are what the committed rules produce today. Earlier rule sets are in git history (`git log scripts/audit.ts src/core`), not restated here.
- Identity neutrality (2026-11-09): an uncorroborated claim is treated exactly like no claim (identity weight excluded, no vow). Only a claim contradicted by a label that names the wallet operator BLOCKs; a person handle or a deposit address contradicts nothing (2026-11-10). Extraction must never penalise being examined.
- Clusters are 1-hop within the audited set. 2-hop kinship needs funder-of-funder data, which this audit did not query.
- Identity is corroborated by the catalog listing name matching the URL host or path, or by a Surf `entity_name` label. Dolphin claim extraction is not run in this audit (census receipts carry `enrichment: skipped`).
- E v2 excludes a labelled-exchange first funder from the payer count. Other exchange or relayer senders are not individually labelled at this scale.
